# 0.4.0 구현·검증 기록

현재 동작은 문서 마지막의 **등록·수정 제한 해제** 내용을 따릅니다. 앞선 작업 기록의 수정 차단·삭제 기능 설명은 당시 구현 기록입니다.

작업 기준: 사용자 제공 고도몰 API 연동 지시서, 2026-10-07.

- 기존 React/Vite + Cloudflare Worker BFF + Supabase 데이터 + Electron 앱 구조 유지.
- 공식 스펙 다운로드: https://devcenter.nhn-commerce.com/godomall5/openapi/specDownload (응답 파일명 `godomall5_openAPI_spec_v1.0_20250616.pdf`, 91쪽). 인증키 안내: https://devcenter-help.nhn-commerce.com/guide/preparation/openapi-guide/userkey.
- POST/UTF-8/XML, `data/header/code=000`, `return`, `total/max_page/now_page`, 최대 100건. 상품 검색은 goodsNm/goodsNo/goodsModelNo/goodsCd.
- 등록/수정은 `data_url`로 일시적인 XML 제공. 수정 필수값 및 옵션/추가상품/필수정보/추가정보 보존 확인. imageUpdate=N.

- 저장 응답을 잃으면 몰별 고유 goodsCd로 확인하며 등록 재전송 금지.
- 키: 공통 `GODOMALL_PARTNER_KEY`, 소매 `GODOMALL_CALLAMEDIA_API_USER_KEY`, 도매 `GODOMALL_CALLAMEDIA1_API_USER_KEY`. 사용자가 Worker Secrets에 직접 입력.
- 도매 회원등급별 가격은 공식 등록 필드에 없음. 기본판매가 매핑을 표시하고 별도 확인을 받음. 초기 구현에는 Chrome 실행기를 유지했으며, 아래 14시 추가 작업에서 API 직접 등록으로 전환했습니다.

상품 식별자는 항상 `(mall_id, goods_no)`입니다. 기존 `product_registrations`의 명시적 상품번호 연결 12건만 이관했으며 초기 API 상태는 `unknown`입니다. 같은 이름이나 다른 몰의 같은 번호로 연결하지 않습니다. `product_items` 삭제 시에도 작업 이력은 남습니다.

실행 전 미리보기는 20분간 유효하며 검토한 관리자만 실행합니다. 같은 작업의 재실행 요청은 기존 상태만 반환합니다. 내부 상품 저장 버전과 원격 상품 지문을 다시 확인하므로 검토 후 바뀐 상품은 재검토해야 합니다. 결과 미확인 상태는 새 API 등록과 기존 실행기의 무조건 재등록도 차단합니다.

등록·수정 XML URL은 256비트 무작위 토큰의 해시로 조회하며 최대 10분, 처리 중에만 접근할 수 있습니다. 처리 종료 후 만료되고 캐시를 허용하지 않습니다. API 키는 XML·작업 이력·프론트엔드에 포함되지 않습니다. XML의 DOCTYPE/외부 엔티티를 거부합니다.

## 키 설정

위치는 **Cloudflare → Workers & Pages → calla-automate → Settings → Variables and Secrets**입니다. 사용자가 직접 입력하며 각각 형식은 **Secret**입니다.

| 이름 | 연결 |
|---|---|
| `GODOMALL_PARTNER_KEY` | 두 몰 공통 `partner_key` |
| `GODOMALL_CALLAMEDIA_API_USER_KEY` | 소매몰 www.callamedia.kr의 `key` |
| `GODOMALL_CALLAMEDIA1_API_USER_KEY` | 도매몰 www.callamedia.co.kr의 `key` |

JSON으로 묶지 않고 각 키 값만 입력합니다. 앱·브라우저나 빌드 전용 환경변수에 설정하지 않습니다. 공통 키가 있으면 한 몰의 사용자 키가 없어도 다른 몰은 독립적으로 사용할 수 있습니다. 대시보드에서 저장·배포 후 **GNB의 소매몰·도매몰 연결 상태 버튼**으로 확인합니다.

## 사용 방법

1. **조회:** 사이드 메뉴 **상품 조회**에서 소매/도매를 선택합니다. 상품명·상품번호·모델번호·자체상품코드로 검색하며 이전/다음 페이지와 다시 조회 버튼을 사용합니다. 조회되지 않은 값은 ‘미확인’ 또는 ‘—’로 표시합니다.
2. **등록:** 기존 리스트에서 상품을 저장한 뒤 행의 **API 등록**을 누릅니다. 또는 **상품 조회 → 저장된 상품 등록**에서 리스트와 상품을 고릅니다. 대상 몰의 브랜드·배송비·공급사를 확인하고 등록할 내용 검토 → 확인 체크 → 등록 실행 순서입니다.
3. **수정:** 조회 목록에서 상품을 열고 **수정**을 누릅니다. 변경 전후 검토 → 확인 체크 → 수정 실행 순서입니다. 저장 직전 최신 원본을 확인하고 저장 후 다시 조회해 변경값과 유지할 데이터를 함께 비교합니다.
4. **삭제:** 상품 상세의 **삭제 검토**에서 몰·상품명·상품번호를 확인합니다. 확인 체크 후 **삭제상품관리로 이동 실행**을 누릅니다. 해당 번호에 대한 성공 응답이 있어야 완료 처리합니다.
5. **결과:** 리스트의 소매·도매 등록 결과와 **상품 조회** 하단 작업 이력에서 확인합니다. 등록 여부와 PC/모바일 노출·판매 상태를 구분합니다. 요청이 끊기거나 확인이 늦으면 이력을 열어 **작업 상태 다시 조회 / 실제 결과 다시 확인**을 사용합니다. 이 버튼은 쓰기 요청을 다시 보내지 않습니다.

최초 확인이 늦으면 최대 3회 재조회하고 `결과 확인 필요`로 남깁니다. 아직 조회하지 않은 상태는 `미확인`으로 표시합니다. 브라우저 새로고침과 앱 재실행 후에도 상태·연결·이력이 DB에 유지됩니다. 운영 상품의 변경은 사용자가 대상과 내용을 확인하고 실행하는 흐름으로만 검증합니다.

## 확인한 업무 흐름

1. **상품 준비:** 요청 리스트를 만들고 상품을 직접 입력하거나 엑셀로 불러온다. 브랜드·상품명·채널별 가격·등록 필요 여부·카테고리·이미지·상세 HTML을 준비한다.
2. **저장 및 전달:** 상품 편집 모달에서 목록 초안에 반영한 뒤 상단 저장으로 공유한다. 모달 취소는 목록을 바꾸지 않는다. 기존 완료 상태는 상품 정보 저장으로 덮어쓰지 않는다.
3. **고도몰 등록:** 현재 로컬 Python 앱이 저장된 목록을 읽는다. 사용자가 목록·채널·상품을 선택하고 별도 Chrome에 로그인하면 폼 입력과 저장을 진행한다. 검토 모드는 입력만 하고 저장하지 않는다.
4. **결과 확인:** 상품+채널별 대기·진행·성공·실패, 상품번호, 오류와 경고를 기록한다. 이미 성공한 채널은 다음 실행에서 제외한다. 중단 요청 시 진행 중인 건을 마친다.

등록 시 PC·모바일 노출은 끄며 **판매 상태는 고도몰 기본값을 유지**한다. 기존 엔진은 한 상품이 실패해도 다음 상품을 계속 처리한다. 위 내용은 참고 소스를 읽어 확인한 동작이며 이번 작업에서 라이브 등록은 실행하지 않았다.

## 기존 구현과 새 화면의 차이

| 항목 | 참고 코드에 있는 것 | 후속 구현이 필요한 것 |
|---|---|---|
| 네이버 스마트스토어 | 상품명, 가격, 등록 필요 여부 | 계정 연결, 채널 카테고리·필수값, 실제 등록, 결과·상품번호 저장 |
| 자동 등록 시작 | 로컬 앱에서 선택 후 실행 | 웹 버튼에서 작업을 생성하고 실행기에 전달하는 계약 |
| 작업 이력·로그 | 상품+고도몰 채널별 최신 결과 | 실행 단위 ID, 시도 이력, 로그, 중단·재시도 및 중복 실행 방지 |
| 전체 완료 | 필요한 소매·도매가 성공하면 `done=true` | 스마트스토어를 포함한 모든 대상 채널의 완료 계산 |
| 채널 연결 상태 | 로컬 Chrome 세션과 수동 로그인 | 웹에 표시할 연결·로그인 필요·권한 오류의 실제 판정 |
| 상품 인덱싱 | 기존 상품 요청 데이터 | 재사용 상품 저장 구조, 상세 HTML 가져오기·갱신·세트 조합 계약 |
| 이미지 클릭 링크 | 조사한 참고 소스의 HTML 생성은 단순 이미지 태그 | 링크 입력·저장·HTML 생성·검증 계약 확인 및 구현 |
| 소매 정가 | 웹 입력·저장 필드 | 현재 Python 엔진은 해당 필드를 입력하지 않으므로 매핑 보완 |

현재 DB의 등록 결과 채널은 `retail/wholesale`만 허용한다. 디자인에 스마트스토어 성공 배지가 있다고 해서 DB와 등록 엔진이 이를 지원하는 것은 아니다. 또한 기존 저장 판정은 상품번호를 확인하지 못해도 성공+경고일 수 있으므로, 결과 화면에서 경고와 재확인 경로를 제공해야 한다.

## 유지해야 할 데이터 계약

- 상품명 HTML 원본은 저장·편집·복사·자동화 전달까지 보존한다. 목록 표시에서만 안전한 텍스트로 변환한다.
- `save_product_draft`와 기존 `/view/?list=<UUID>`, `html[data-automation-ready]`, `script#automation-data` 소비 계약을 변경할 때는 기존 자동화와의 호환을 검증한다.
- `done/done_at`과 행 선택은 별도다. 상품 정보 저장이 등록 완료를 되돌리지 않게 한다.
- 카테고리 코드는 앞자리 0을 포함한 문자열이며 소매·도매가 독립적이다.
- 소매 정가와 소매 판매가를 구분한다. 네이버 가격은 현재 소매 판매가와 연동된다. 공란 가격을 임의로 0원으로 바꾸지 않는다.
- 이미지 정상 검사는 검사 시점의 결과다. 주소가 바뀌면 다시 검사하고, 준비 완료 판단과 실행 전 채널별 필수값 검증을 구분한다.

## 사이드바 구현 기준

`Sidemenu-prompt.md`의 구조와 동작을 가져오고 색·서체·아이콘은 새 디자인 시스템에 맞춘다. 문서의 Tabler 아이콘 예시보다 사용자가 지정한 **SF Symbols Pro**를 우선한다.

- 기본 펼침 260px, 접힘 60px. 크기 조절형은 180–400px이고 드래그·키보드 조절·더블클릭 초기화를 제공한다. 키보드는 좌우 16px, Shift+좌우 48px, Home/End 최솟값·최댓값을 따른다.
- 헤더·스크롤 가능한 메뉴·푸터를 분리한다. 참고 헤더는 52px이며, 현재 디자인의 헤더 규격은 화면과 함께 맞춘다. 긴 메뉴가 헤더·푸터를 밀어내지 않게 한다.
- 접힘 상태에서는 레이블·섹션 제목·배지를 숨기고 아이콘을 유지한다. 메뉴 이름 툴팁과 접근 가능한 이름을 제공하고, 접힌 로고로 펼칠 수 있게 한다.
- 활성 메뉴는 둥근 핑크 배경과 흰색 텍스트·아이콘으로 표시한다. 호버·2px 키보드 포커스·비활성을 별도 표현한다. 현재 위치에는 `aria-current`, 하위 메뉴에는 `aria-expanded/controls`를 연결한다.
- 하위 메뉴는 chevron, 들여쓰기, 펼침/접힘을 지원한다. 디자인 문서의 동작 설명은 실제 인터랙션 구현 완료를 뜻하지 않는다.
- 너비 전환 240ms, 레이블 120ms, 항목 색상 150ms를 기준으로 한다. 움직임 줄이기 설정에서는 모션을 생략한다. 크기 조절 중 너비 애니메이션은 끈다.
- 플로팅형은 바깥 여백·둥근 모서리·테두리·그림자를 적용한다. 기본형은 본문과 경계선으로 구분한다.

## GitHub·Cloudflare 후속 구현

참고 `wrangler.jsonc`는 정적 자산 제공 설정이다. 기존 자동화는 macOS Chrome을 실행하고 로컬 CDP에 연결하는 Python 프로그램이므로, **홈페이지를 Worker로 배포하는 것만으로 기존 자동화가 서버에서 실행되지는 않는다.**

후속 개발에서는 먼저 웹·저장소·실행기의 역할과 연결을 정해야 한다. 기존 로컬 실행기를 유지할지, 별도 실행 서비스로 옮길지, 각 판매 채널의 공식 API를 사용할지에 따라 로그인·작업 상태·중단·재시도 계약이 달라진다. 외부 채널 API 사양과 권한은 구현 시점에 확인한다. 채널 자격증명은 브라우저 코드나 저장소에 포함하지 않고 서버 측 비밀값으로 관리한다.

구현 검증은 상품 작성→저장→실행 요청→채널 결과→전체 완료까지 이어져야 한다. 실제 저장 여부가 불확실한 건은 무조건 재등록하지 않고 채널에서 확인할 수 있게 한다. 로컬 검사와 화면 미리보기 이후 GitHub 푸시·Worker 배포·배포 주소 확인을 별도 완료 단계로 기록한다.

현재 인계 문서는 디자인 의도와 소스에서 확인한 제약을 전달한다. 웹 구현·스마트스토어 연결·라이브 상품 등록·배포의 완료 증거로 사용하지 않는다.

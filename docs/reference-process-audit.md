# CALLA-AUTOMATE 참고 프로세스 조사

조사일: 2026-09-30. `../CALLTO/Product-Share-Tool`과 `../상품 등록 자동화`의 로컬 소스를 읽어 확인했다. 라이브 상품 등록, DB 변경, 기존 소스 변경은 하지 않았다. 두 폴더 및 상위 경로에서 적용할 `AGENTS.md`는 발견하지 못했다. Git 상태 확인은 로컬 Xcode 라이선스 오류로 실행되지 않아 현재 배포 버전과의 일치 여부는 확인하지 않았다.

## 핵심 결론

현재 구조는 **웹에서 등록 요청 작성 → 저장된 상품을 로컬 자동화 앱이 조회 → 사람이 고도몰 로그인 → 소매몰·도매몰 등록 → 결과를 DB에 기록 → 웹에서 확인**이다. 웹이 자동화를 실행하는 구조는 아니다.

네이버 스마트스토어는 상품명·가격·등록 필요 여부를 작성하는 기능까지만 있다. 참고 코드에는 네이버 등록 엔진, API 연결, 인증, 네이버 카테고리, 네이버 등록 결과가 없다. 새 홈페이지는 네이버까지 확장할 화면을 설계하되 현재 구현된 기능과 구분해야 한다.

## 현재 데이터 규칙

- 상품명 원본에 HTML이 있을 수 있다. 보이는 목록 텍스트와 저장·복사·자동화에 전달할 원본은 구분해야 한다. 현재 `js/ui.js:77-88,111`에서 표시용 텍스트를 만들며 `js/api.js:99`는 원본을 저장한다.
- 네이버 상품명 자동 모드는 자사몰 상품명에서 `/`만 제거한다. 수동 모드가 있고 50자 초과는 경고만 한다. 네이버 가격은 소매몰 판매가와 연동된다 (`js/workspace.js:95-116`).
- 소매 정가, 소매 판매가, 도매 베이직, 도매 마스터, 네이버 가격 필드가 존재한다. **현재 로컬 고도몰 엔진은 소매 정가를 읽거나 입력하지 않는다.** 도매 정가에는 소매 판매가를 입력하고, 베이직 공란은 소매 판매가, 마스터 공란은 베이직을 사용한다 (`상품 등록 자동화/db.py:29-74`, `godomall.py:281-304`).
- 카테고리는 앞자리 0을 보존하는 문자열이고 소매/도매가 독립적이다. 현재 네이버 카테고리 계약은 없다 (`js/automation-core.js:147-158`).
- 고도몰 등록 시 PC/모바일 노출 안 함으로 입력한다. 브랜드/썸네일/상세 HTML이 없거나 썸네일 업로드가 실패해도 일부는 경고로만 남기고 저장을 진행한다 (`godomall.py:80-100,375-401`).
- `pending/running/success/failed`는 상품+채널별 결과다. 실행 작업의 이력 테이블이나 각 시도별 이력은 없으며 재시도 시 최신 결과를 upsert한다 (`db.py:184-213`).

## 새 홈페이지 설계에 필요한 개체와 상태

| 개체 | 주요 데이터 | 주요 화면/액션 |
|---|---|---|
| 등록 요청 목록 | 제목, 작성자, 작업일, 전체/완료/미처리 수, 저장 상태 | 목록 탐색·검색·생성·정보 수정·공유·삭제 |
| 상품 | 원본 상품명, 채널별 상품명, 브랜드/모델/원산지, 가격, 이미지, 상세 HTML, 메모 | 상세 편집·복제·삭제·일괄 설정·엑셀 가져오기 |
| 채널별 등록 대상 | 필요 여부, 채널 카테고리, 채널별 필수값 | 소매/도매/스마트스토어 필터, 채널 검토 |
| 준비 검사 | 정보 부족, 이미지 확인 필요, 준비 완료 | 누락 위치 이동·이미지 재검사·미리보기 |
| 자동화 작업(새로 필요) | 선택 상품/채널, 진행 수, 현재 상품, 실행 시작/종료 시각 | 실행 전 검토·시작·중단·로그·결과 요약 |
| 채널별 등록 결과 | 대기/진행/성공/실패, 상품번호, 오류, 경고 | 상세 보기·몰 열기·실패 재시도·결과 확인 |
| 채널 연결(새로 필요) | 채널 계정/연결 상태, 인증 상태 | 연결·재인증·연결 오류 해결 |
| 공통 설정 | 브랜드/별칭, 채널별 카테고리, 이미지 폴더 | 검색·추가·수정·사용 중지 |

준비 상태, 채널별 등록 상태, 전체 작업 상태를 같은 배지로 합치지 않는 것이 중요하다. 이미지 검사 통과가 실제 등록 성공은 아니고, 일부 채널 성공이 전체 완료도 아니다. 실행 수는 상품 수와 채널별 등록 건수 둘 다 표시할 수 있어야 한다.

## 디자인 단계에서 반영할 간극

1. **네이버 완료 계산:** 현재 `CHANNELS = ("retail", "wholesale")`라 네이버 등록 필요 여부와 무관하게 두 고도몰만 성공하면 전체 완료 처리한다. 스키마도 네이버 상태를 허용하지 않는다 (`상품 등록 자동화/db.py:13,215-224`; `CALLTO/Product-Share-Tool/supabase/migrations/20260907120000_product_registrations.sql:5-6`). 새 화면의 전체 완료는 선택한 모든 대상 채널을 기준으로 정의해야 한다.
2. **웹 실행 기반:** 참고 Cloudflare 설정은 정적 자산 제공만 한다. Python 앱은 로컬 macOS Chrome에 CDP 연결한다. 웹 배포만으로 기존 자동화가 서버에서 실행되지는 않으므로, 이후 구현에서 실행 서비스/로컬 에이전트 또는 채널 API 연동을 결정해야 한다 (`wrangler.jsonc:2-13`; `상품 등록 자동화/browser.py:28-56`).
3. **성공/확인 필요 구분:** 현재 저장 후 URL/iframe 변화로 성공 판정할 수 있고 상품번호를 못 찾으면 성공+경고로 남긴다. 새 결과 화면에는 경고 및 확인 필요를 숨기지 않는 자리가 필요하다 (`godomall.py:407-438`; `core.py:146-150`).
4. **준비 완료 의미:** 웹의 준비 검사는 카테고리·상품명·썸네일·상세 이미지를 본다. 가격/브랜드 매칭/채널별 추가 필수값을 모두 보장하지는 않는다 (`js/automation-core.js:97-111`; `docs/automation-contract.md:109`). 실행 전 채널별 체크리스트가 필요하다.
5. **문서와 로컬 UI 차이:** README에는 준비 상태 필터/자동화 정보 표시가 남아 있으나 로컬 `js/workspace.js:26-31`, `js/automation-editor.js:21`에는 필터/요약이 비활성화되어 있다. README의 화면 목록을 그대로 현재 화면이라고 가정하면 안 된다.

이 보고서는 디자인에서 필요한 데이터와 행동을 구체화하는 소스 조사 결과다. 신규 자동화 및 네이버 연결 구현, 라이브 저장 검증, GitHub 푸시, 배포는 수행하지 않았다.

# 고도몰 저장 완료 팝업 인식과 연속 등록 수정 — 2026-10-06

## 확인한 원인

설치된 앱 0.3.2 / 실행기 1.1.2는 자동 목록 검색·상품 상세 대조를 제거한 상태였지만, 실제 저장 완료 신호를 놓쳤습니다. `goods_ps.php`는 HTTP 200 응답에서 `BootstrapDialog`의 메시지를 **저장이 완료되었습니다.**로 설정하고, 3초 뒤 팝업을 닫으며 `target.location.reload(true)`로 등록 폼을 새로고침합니다. 기존 판정은 네이티브 alert 또는 상품 목록으로의 이동만 처리해 60초 뒤 `needs_review`로 멈췄습니다.

- EA508은 이미 소매 상품번호 `1000008188`로 저장되어 있었습니다. 원래 시도·상품 정보·목록·상세를 기존 읽기 전용 복구 경로로 대조한 후 상태를 동기화했습니다.
- 원래 선택했던 다음 대기 상품 WM3210P 한 건의 실제 저장 응답으로 원인을 재현했습니다. 상품번호 `1000008189`도 재저장 없이 복구했습니다.
- 수집한 응답에는 동일 주소로 향하는 보조 AJAX 요청도 있었습니다. 저장 성공 판정은 폼을 제출한 navigation POST 응답만 사용하도록 제한했습니다.

## 변경 내용

- 실행기 `1.1.5`: 저장 처리 응답의 `BootstrapDialog` 메시지를 읽어 완료를 인식합니다. 실제 저장 POST의 완료 문구가 있어야 성공합니다.
- 일반 HTTP 200, 확인 질문, 단순 페이지 문구, 보조 AJAX, 다시 표시된 입력 폼을 성공으로 처리하지 않습니다. 명확한 오류는 완료 문구보다 우선합니다.
- 저장 버튼은 한 번만 누릅니다. 상품별 목록 검색·상세 대조나 검토 대기를 추가하지 않았습니다. 응답에 상품번호가 없으면 기존 계약대로 번호 없이 완료 응답과 시도 정보를 동기화합니다.
- 일시적인 읽기 요청의 연결 끊김·잘린 응답·429·서버 장애는 최대 세 번 재시도합니다. 새 등록 선점 등 POST 요청은 이 재시도에서 제외하며, 로그인·권한·보안 검사 거부도 반복하지 않습니다. 각 재시도는 현재 로그인 세션을 사용합니다.
- 등록 화면 GET이 일시적으로 중단되거나 연결이 끊겨도 입력 전에 최대 세 번 다시 엽니다. 접근 거부는 재시도하지 않습니다. 지속적인 중단 시에는 해당 건만 실패 처리하고 다음 상품으로 진행합니다.
- 기존 상태 동기화, 원래 실행 버전 확인, 중복 등록 차단과 수동 복구 기능을 유지했습니다.
